# 스트리머 방송 시작·종료 기록 기획서

## 목적

채팅방 참여자가 방송국을 따로 확인하지 않아도 스트리머의 방송 시작과 종료를 채팅 기록에서 확인하고, 종료된 방송은 다시보기 썸네일을 눌러 채팅 도구 안에서 재생할 수 있게 한다.

## 사용자 흐름

1. 스트리머 방송이 시작되면 해당 채팅방에 `방송 중` 기록 카드가 자동으로 한 번 올라온다.
2. 방송이 종료되면 새 메시지를 추가하지 않고 시작 기록 카드의 상태와 종료 시각을 갱신한다.
3. SOOP 방송국에 다시보기가 등록되면 같은 카드에 썸네일과 다시보기 제목을 추가한다.
4. 참여자가 썸네일을 누르면 SOOP 다시보기가 채팅 도구의 영상 플레이어에서 재생된다. 원본 링크도 기존 채팅 도구의 원본 보기 버튼으로 열 수 있다.
5. 관리자 방과 스트리머 방은 같은 흐름을 사용한다. 테스트 전용 방은 공개 방 목록에 없으므로 자동 감시 대상에서 제외한다.

## 감지와 다시보기 연결

- 전역 반복 스케줄러는 사용하지 않는다. 승인 참여자 수가 0명에서 1명 이상으로 바뀐 방만 감시 작업을 시작하고, 해당 방의 다음 확인 시각에 Cloud Tasks 작업을 하나씩 예약한다. 방송 중인 방과 SOOP 응답 오류는 5분, 방송 중이 아닌 방은 10분 간격으로 상태를 확인한다.
- 승인된 참여자 수가 1명 이상인 방만 새 방송 감지를 시작한다. 공개 방은 참여자 승인·차단·방 설정 처리에서 함께 갱신하는 `publicRooms/{roomId}/memberCount`를 사용하고, 비공개 방은 공개 프로젝션에서 인원 수를 숨기므로 서버가 관리하는 `rooms/{roomId}/meta/memberCount`를 읽는다. 두 값은 방 소유자를 제외한 활성 참여자 수다.
- 참여자가 0명이 되면 해당 방의 예약 작업을 취소하고 감시를 끈다. 이미 실행을 시작한 작업은 세대 번호와 참여자 수를 다시 확인해 오래된 결과를 저장하지 않는다. 진행 중 카드와 대기 중인 다시보기 상태는 보존하며, 참여자가 다시 들어오면 즉시 새 작업을 예약한다. 참여자 없이 지나간 방송은 과거 기록으로 만들지 않는다.
- 감시 상태, 세대 번호, 예약 작업 ID와 다음 확인 시각은 서버 전용 `streamerMessenger/broadcastMonitor/{roomId}`에 저장한다. 한 시점에 방마다 예약 작업은 하나만 유지한다. Cloud Tasks 작업은 동시에 최대 8개까지 처리한다.
- 방과 방송 ID를 이용해 20자 고정 메시지 ID를 만든다. 반복 실행이나 네트워크 재시도에도 같은 방송 카드가 중복 생성되지 않는다.
- 종료와 다시보기 연결 시 같은 카드의 채팅 정렬 시각을 갱신해 최근 메시지 화면에서도 상태 변경을 놓치지 않게 한다. 방송 시작 시각은 카드 본문에서 계속 확인할 수 있다.
- SOOP 다시보기 API를 종료 후 약 5분, 10분, 30분, 90분, 6시간, 18시간, 36시간에 조회한다. API 오류는 재시도 일정을 소모하지 않고 15분 후 다시 확인한다. Cloud Tasks 처리 지연에 따라 조회 시각이 늦어질 수 있다.
- 방송 제목, 등록 시각, 영상 길이를 함께 비교해 가장 그럴듯한 최근 다시보기만 연결한다. 맞는 항목을 찾지 못하면 약 36시간 후 카드에 다시보기를 찾지 못했다고 표시한다.
- SOOP의 방송 시작·종료 시간을 별도 실시간 이벤트로 받는 구조가 아니므로 기록 시각은 서버가 방송 상태 변화를 확인한 시각이다. 시작 감지는 일반적으로 최대 약 10분, 종료 감지는 최대 약 5분 늦을 수 있다.

## 저장과 권한

- 기록 카드는 `streamerMessenger/chat/{roomId}/streamerTimeline`과 `streamerMessenger/chat/{roomId}/broadcast`에 같은 ID로 저장한다. 서버가 Admin SDK로만 기록하므로 브라우저 쓰기 권한이나 공유 RTDB 규칙 변경이 필요 없다.
- 참여자는 기존 공개 메시지와 동일한 권한으로 카드를 실시간 확인한다. 방 소유자는 기존 타임라인에서 확인한다.
- 7일이 지난 메시지는 기존 `messengerPurgeExpiredData`와 공개 대화 아카이브 경로를 통해 정적 압축 아카이브에 보관된다. 방송 기록을 별도 단기 경로에 두지 않는다.

## 화면

- 메시지 한 건을 방송 카드로 렌더링한다. 방송 중 배지, 방송 제목, 시작 시각을 표시한다.
- 종료 후에는 종료 상태와 종료 시각을 추가한다. 다시보기 조회 중 또는 미등록 상태를 안내한다.
- 다시보기가 연결되면 반응형 썸네일과 재생 버튼을 표시한다. 모바일과 데스크톱 모두 채팅 도구 플레이어를 사용한다.

## 검증 항목

- 방송 시작 상태에서 카드가 한 건만 생성되고, 반복 감지·새로고침에도 중복되지 않는지 확인한다.
- 참여자 0명인 방은 방송 상태 및 다시보기 API를 모두 조회하지 않고, 0→1명 복귀 시 상태 감지와 대기 중인 다시보기 검색을 재개하는지 확인한다.
- 종료 감지 후 기존 카드가 종료 상태로 갱신되는지 확인한다.
- 다시보기 검색 성공·미등록·SOOP API 오류에서 상태와 재시도가 올바른지 확인한다.
- 관리자/호스트/참여자 메시지 읽기 권한, 모바일·데스크톱 카드 표시와 도구 내 재생을 확인한다.
- 7일 아카이브가 기존 공개 메시지처럼 해당 카드를 보존하는지 확인한다.

## 구현 범위

- `functions/src/messenger.js`: 참여자 수 변경 트리거, 방별 Cloud Tasks 감시 작업, 중복 방지 ID, 방송 종료 및 다시보기 탐색·연결.
- `functions/index.js`: `messengerScheduleStreamerBroadcastHistory`, `messengerProcessStreamerBroadcastHistory` export.
- `js/app.js`, `styles.css`: 자동 방송 카드와 채팅 도구 내 다시보기 재생 UI.
- `database.rules.json`: 변경하지 않음.
